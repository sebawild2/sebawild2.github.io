Every correct algorithm needs Ω(n) time

“We have to read all the numbers.” — an adversary argument, played out step by step. Suppose some algorithm solved the maximum subarray problem in o(n) time. Then on large enough inputs it must stop before it has looked at every entry. Watch what the adversary does with the entry it skipped.

Conclusion

The algorithm read exactly the same values in both cases, in the same order, so it took the same execution path and produced the same output. But I₁ and I₂ have different correct answers, so at least one of the two outputs is wrong — contradicting correctness.

Hence no correct algorithm can skip an entry on every input, and reading n entries costs Ω(n). Together with the divide-and-conquer solution this places the complexity of the maximum subarray problem between Ω(n) and O(n log n) — and the linear sweep closes the gap: the problem is Θ(n).
