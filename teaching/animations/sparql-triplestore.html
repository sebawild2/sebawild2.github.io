SPARQL on a triple store  ·  matching a graph pattern, step by step

A graph database stores its graph as a set of triples (subject, predicate, object) — one row per edge. A SPARQL query is a small pattern graph with variables; answering it means finding every way to fit the pattern into the data. The core algorithm is simple: take the triple patterns one at a time, turn each into a range lookup in a sorted copy of the triples, and grow a table of variable bindings, one pattern per column-set. Rows that find no continuation die; the rows that survive all patterns are the answers. Hover triples, edges and binding rows to see how they correspond; drag nodes, zoom with the wheel, and drag the divider between the columns to make room.

Data: one triple per line, subject predicate object, an optional trailing . (N-Triples / Turtle style, prefixed names such as :Alice or ex:Alice, literals in "quotes"). Lines starting with # are comments. Only the part after the last : is drawn as the label.

Drawing: add @pos :Alice 120 40 lines to fix where a node is drawn (any units, y grows downwards; the picture is rescaled to fit). Nodes without a position are laid out automatically.

Query: SELECT ?x ?y WHERE { s p o . s p o . } — a basic graph pattern only, no FILTER, OPTIONAL or UNION. Any of the three positions may be a variable, including the predicate. SELECT * selects all variables. The order of the patterns in the text is the “as written” execution order.
