The inexact turnpike problem  ·  interval backtracking

Real measurements come with errors. In the inexact turnpike problem every toll is only known up to an additive error: the input is a multiset of intervals [d, d̄], and we ask for exit positions 0 = S[0] < … < S[n−1] together with a bijection between the n(n−1)/2 pairs of exits and the intervals, such that every pair's distance lies in its interval. This variant is strongly NP-hard, so the pseudopolynomial trick is gone; what remains is search. The algorithm below extends largest-first backtracking: every exit is an interval of possible positions, kept as tight as the constraints collected so far allow, and the bijection is built pair by pair.

Input
One interval per line, as lo hi or lo..hi (integers, lo ≤ hi); a single number d is the exact distance [d, d]. The number of intervals must be n(n−1)/2 for the number of exits n. Lines starting with # are ignored. The generator above produces such a list from a true set of exits: every distance is measured with an error drawn uniformly from {−ε, …, ε}, and the interval is the measurement ±ε, so the true distance is always covered. At most 10 exits (45 intervals).
