Move to Front

The source alphabet lives in a self-adjusting list. A character is encoded by its old position in that list, and is then moved to the front. Clusters of few characters therefore turn into many small numbers — which is what makes the following compressor's job easy. MTF alone compresses nothing.

Input format

Encoding. The input box holds the source text S. Spaces are drawn as ␣ and are ordinary characters of the alphabet — but note that A–Z does not contain a space, so use the auto or custom alphabet if your text has one.

Decoding. The input box holds the positions, separated by spaces:

8 13 6 7 0 3 6 1 3 4 3 3 3 18

Alphabet. A–Z reproduces the lecture example: the list starts as A B C … Z and codewords are positions in [0..26). auto uses only the characters occurring in S, in sorted order, which keeps σ small and the picture readable. custom takes the characters in the order you give them — note that the pseudocode says sorted order, so a custom list that is not sorted departs from the lecture convention, and is only offered for experimenting.

The four sub-steps. Each character is handled in four snapshots: read its position, lift it out of the list leaving a gap, slide it to the front, and finally close the gap and re-space the list. Only the last of these is a state the algorithm itself ever sees; the middle two exist to make the motion visible.
