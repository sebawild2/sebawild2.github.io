Arithmetic coding  ·  renormalization and fixed precision

Zooming into an interval needs Ω(n) bits of precision — unless the leading bits are written out as soon as they are decided, and the interval is doubled to make room again. Once [ℓ, ℓ+p) lies in the lower half the code must start with 0; in the upper half, with 1. The awkward case is an interval straddling ½: it is inside [¼, ¾), so the next two bits are 01 or 10 — one outstanding opposite bit is remembered and emitted later. With that, ℓ and p never leave a fixed range, and the whole coder runs in fixed-precision integer arithmetic.

model uniform | fixed | adaptive
alphabet 0 1 2 — the symbols, in the order in which they divide the interval.
eof 0.15 — probability of the end-of-text symbol $, which takes the topmost slice. eof 0 means the text length is known to the decoder instead.
p a 0.425 — a symbol's weight, for model fixed; weights are normalised to sum to 1 − P($).
text 21101 — the source text.
n 5 — how many symbols to decode when there is no $.

In the fixed-precision setting the model's probabilities are turned into the smallest integer frequency counts that represent them exactly, and t is their sum; the coder needs t ≤ 2f with f ≤ b−2, so a model with awkward probabilities forces a larger b.
