Input. Patterns separated by spaces or commas, plus one text. Everything is in the URL, so Copy link gives a permalink to the example.

The three stages. The trie stores all patterns at once, sharing common prefixes. Then two kinds of link are added, breadth first: the suffix link of a node v points to the node for the longest proper suffix of v's string that is still in the trie — this is exactly the KMP failure link, generalised to a set of patterns — and the output link chains to the next node on the suffix-link path that is itself the end of a pattern, so all patterns ending at the current position can be reported in time proportional to their number. Finally the text is scanned: a missing edge means following suffix links (which consume no character), and every arrival reports along the output-link chain.

Colours follow the two link types: red dashed for suffix links (the same style as the failure links on the KMP page) and blue dotted for output links. Nodes and links appear as the algorithm creates them, not before.

Suffix links pointing at the root are not drawn — every node has one unless stated otherwise, and drawing them all buries the picture. The checkbox hides the links entirely, which is useful when showing the plain trie.

Cost. Θ(total pattern length) to build, Θ(n) to scan and Θ(number of occurrences) to report; the chips count transitions, suffix-link steps and reported matches separately. Try the nested patterns aa, aaa, aaaa on aaaaaa to see the output-sensitive part dominate.
