Overlap graphs  ·  from a string to a Hamiltonian path

A sequencing machine never hands us the genome; it hands us the k-mer composition — the multiset of all length-k windows, in no particular order. The overlap graph puts one vertex per read and an arc rirj whenever the last k−1 letters of Ri are the first k−1 letters of Rj; an assembly is then a Hamiltonian path. Watch the graph being built in the order the reads came from the string — and then watch that order be taken away again. Hover a vertex to see its neighbours.

Lines starting with # are ignored, so a file can hold several examples with comments. Of the remaining lines, the one that is a small integer is k; the other one is the input (either order, as in the Rosalind “string composition” format):

3
TAATGCCATGGGATGTT

A line with several whitespace-separated words is instead read as the k-mer multiset ℛ itself — then k is the word length and there is no string to slice up, so the first phase just lays the reads out:

TAA AAT ATG TGT GTT ATG

For the “nice” layout of the graph the reads have to be put in some order that makes the backbone a path: with a string that is the order they were cut out of it; with a bare multiset the page solves the assembly problem first and uses that order (and says so). At most 26 reads — beyond that the picture is unreadable, and the point of it is lost.
