Hamming codes  ·  locating a flipped bit

Several parity bits, each covering a cleverly chosen subset of the positions: check Cj covers exactly those Bi whose index has a 1 in binary digit j. If a single bit flips, every check covering it is violated and no other is — so the violated checks, read as a binary number, spell out the position of the error, parity bits included. Click any bit in the channel to flip it and watch the syndrome point at it. Hovering isolates one strand of the picture: a data bit shows the parity bits it feeds, a parity bit shows the data it is computed from, and a Cj shows that check alone.

Small screen: this is the compact demo — the block, the scrubber and the syndrome. The encoding and decoding recipes with live highlighting are on the desktop version.

Input
One directive per line; # starts a comment.

l 3 — the block has n = 2l − 1 bits, of which l are parity bits, so the message has k = n − l bits. l 3 is the (7,4) code of the lecture; n 7 works as well.
message 1011 — the k data bits, written Dk−1 … D0. Shorter input is padded with zeros on the left.
flip 5 — a channel error at position i, i.e. bit Bi arrives inverted. Repeat the directive, or list several indices, for several errors. Position 0 is the extra overall parity bit, if there is one.
extended yes — add one parity bit over the whole block, giving distance 4: any 2-bit error is then detected instead of being “corrected” into a third wrong word.
