About this page — input format, conventions, open questions

Input. Any strings. If text and pattern consist of digits only they are read as decimal numbers (character value = digit); otherwise character codes are used and R should be at least σ (256 works for ASCII). R and M are free parameters, so collisions can be provoked on purpose — but M has to be larger than R, otherwise a single character no longer fits into one residue; the page refuses smaller moduli.

The three variants. First, every fingerprint is computed from scratch — correct, but Θ(m) per guess and therefore Θ(mn) overall, no better than brute force. Second, the rolling hash. The table above the update shows what is really going on: the window as a number in radix R, Horner's scheme pulling out one factor R, dropping the leading character and adding the new one — and then exactly the same computation with the "mod M" moved inside, which is the only thing that keeps the numbers small enough for Θ(1) arithmetic. Third, the modulus is drawn at random for each run — press "Draw a new M" to re-roll. A fixed modulus can be defeated by a text built against it; a random one makes the expected number of false positives about n/M whatever the input is.

Cost. Hash operations, character comparisons — which only happen when the fingerprints agree — and the number of false positives, next to the theoretical rate 1/M. Set the random modulus below 100 to see collisions regularly, which is the point of the character-wise verification: a fingerprint hit is evidence, not proof.
