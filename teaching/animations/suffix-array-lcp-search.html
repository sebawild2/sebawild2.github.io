Suffix Array Search with LCP

Binary search for a pattern P among the sorted suffixes. Besides the two boundaries a and b, the search remembers how many characters of P each boundary suffix already matches, ℓa and ℓb. With LCP values between suffixes, it never compares the same character of P twice as equal — and sometimes decides a step without any comparison at all.

  Input format
  

    
One item per line; lines starting with # are comments.


hannahbansbananasman     the text T; $ is appended (it must not occur elsewhere)
anarchy                  patterns, one per line — the first one is loaded
anna

    
Type _ for a space (drawn as ␣). The end-of-word character $ is the smallest
      character and may not occur in a pattern; all others are ordered by their character code.

    
Notation, as in the pseudocode: T = T[0..n] with T[n] = $, and Ti = T[i..n] is the suffix
      starting at i. The rows are ranks: row r shows TL[r], the suffix of rank r. a, b and m are always
      ranks. Row n+1 is virtual and larger than every suffix. LCP[r] = LCP(TL[r−1], TL[r]), so
      LCP(TL[a], TL[m]) = min LCP[a+1..m] = LCP[RMQLCP(a+1, m)], where RMQLCP(x, y)
      is the index of the (leftmost) minimum in LCP[x..y]: one range-minimum query, treated as a black box here.

    
Counting. Every evaluation of P[ℓ] = T[L[m]+ℓ] is one character comparison; the decision after the
      loop reuses the result of the last one. "Plain binary search" is the same search comparing P with TL[m]
      from position 0 every time — it visits the same midpoints, since it takes the same decisions.

    
Mouse only. The pattern buttons switch patterns; dragging across T searches for the selected substring;
      clicking a phase below the progress bar jumps to its start. The slider above the suffixes squeezes long suffixes;
      the bar between drawing and pseudocode can be dragged (double-click resets it).
