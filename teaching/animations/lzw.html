Lempel–Ziv–Welch

A variable-to-fixed code: every codeword is an index into a dictionary D that both sides grow as they go. Encoding extends the current phrase x as long as D knows it; decoding replays the same growth, one step behind — which is exactly why the bootstrap case exists.

Input format

Encoding. The input box holds the source text S. Type _ to get a space if you prefer, or just press the space bar; spaces are drawn as ␣ and are ordinary characters.

Decoding. The input box holds the codewords, separated by spaces:

67 65 78 32 66 129 133 83

Side by side. The input box holds a source text; it is encoded, and the resulting codewords are fed straight back into the decoder.

Alphabet. Three choices. ASCII 0–127 is the setting used on the slides: every character is its own ASCII code and the first free codeword is 128. auto uses only the characters that occur in S, numbered 0…σ−1, which keeps the numbers small for hand-checking. custom takes a list of characters, numbered by position. Only the entries of D that are actually reachable are drawn — the ASCII table is not shown in full, exactly as on the slides, where the unused stretches are replaced by ….

Dictionary trie. The encoding pseudocode stores D as a trie, so that containsKey(xc) is one step down from the node for x. The decoder does not need a trie: it looks up D[q] in an array. That asymmetry is visible in the two views.
