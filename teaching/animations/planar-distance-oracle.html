Distance oracles  ·  paying for speed with space

A distance oracle answers d(u,v) queries for a fixed graph. Dijkstra's algorithm answers each query from scratch; a full distance table answers instantly but stores n² numbers. In between sits the idea that a separator makes precise: any path between two pieces passes through the separator, so distances to the separator are all one needs to store. Choose a strategy, then click two vertices (or type them) to ask a query. Edge labels are lengths.

Pseudocode
The same trade-off for large n n
With the separator idea applied recursively (each piece is split again by its own separator until pieces are tiny), a query walks down the recursion, adding up O(√n) + O(√(2⁄3n)) + … = O(√n) candidates, and the stored distances add up to O(n√n) in total, since every recursion level stores at most O(√n) numbers per vertex and the piece sizes shrink geometrically. The numbers on the left use these bounds with constant 1 and Dijkstra with a binary heap; they are meant to show the shape of the trade-off, not to be exact. The general rule: space × query time ≈ n², and the separator lets one choose where on that curve to sit.
Input
First line V E, then one edge per line u v w with a positive length w (missing lengths default to 1; the EdgeWeightedGraph format), then exactly V lines x y giving the drawing. The drawing is the planar embedding used to find the separators, so edges must not cross. Lines starting with # are ignored. The same file works in the graph editor and on the planar-separator page.
