About this page — input format, conventions, open questions

Input. Text, pattern and (optionally) the alphabet Σ as plain strings; leave Σ empty to use all characters occurring in T and P. The characters of P are always in Σ. All inputs live in the URL, so Copy link produces a permalink to the example.

What the state means. Being in state q after reading T[0..i] means: the last q characters read are exactly P[0..q), and no longer prefix of P ends here. The alignment rows make that explicit — characters in parentheses are known to be equal from the state alone and are never looked at again, the plain character is the one just read, and a red character is the one that killed the guess. The automaton never goes back in the text: one table lookup per character, no matter how badly things go.

The NFA. Here a whole set of states is active. Each active state q ≥ 1 is one alignment of the pattern, shifted so that its first q characters cover the last q characters read; all of them have to be tracked simultaneously, which is what makes the set simulation slow. State 0 carries the Σ-loop and is therefore always active — every position is still a possible start.

Cost. DFA: one table lookup per text character, plus Θ(mσ) time and space for the table (both shown as chips). NFA: the number of edges inspected.
