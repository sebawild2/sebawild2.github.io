Compression pipelines

A chain of data nodes joined by processing stages. Every node is a text over some alphabet — characters, numbers, or bits — and every stage maps one node to the next. Transformations like BWT and MTF never shorten anything; coders like Huffman and Elias γ do. A coder's output is itself a text over {0,1}, so it can be fed into further stages.

Chaining coders. A coder turns its input into a bit string, which is a perfectly good text over the alphabet {0,1}. So a coder may sit in the middle of a chain and be followed by more stages. Some of those combinations are pointless and it is worth seeing why: binary Huffman on a two-symbol alphabet always spends exactly one bit per symbol, so Huffman → Huffman changes nothing. Others are not pointless at all — a fixed-length code leaves a very regular bit pattern, and RLE (binary) → Elias γ on top of it can beat the fixed-length code itself.

What is not counted. Every figure is the size of the body. The cost of transmitting the code table is not included, which flatters Huffman, especially on short inputs; Elias γ and RLE need no table at all. See the Huffman page for what a code header actually costs.

Invertibility. Every stage here is invertible given its parameters, so any chain is a genuine compressor, not a lossy one.
